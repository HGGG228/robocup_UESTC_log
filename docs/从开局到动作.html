智能体：从拿到地图到第一个动作

左边蓝色是服务器做的事，右边黄色是智能体做的事。开局只有一次，第 6 步开始每回合循环。

1
服务器 · 建立连接

分配单位，发"开局大礼包"

  • 智能体发 AKConnect（队名 + 想控制的兵种类型）
  • 服务器找到空闲单位，回 KAConnectOK，里面装三样东西：你的实体 ID、初始可见实体集合、一份裁剪过的配置
  • 连接窗口有 5 分钟（kernel.startup.connect-time）
2
服务器 · 这一步决定"你能看到什么"

开局地图 = 全图静态骨架，但关键信息被抠掉

  • 给全部道路：节点坐标、长度、邻接关系、轮廓顶点
  • 给全部建筑：坐标、形状、面积、邻接
  • 给全部队友单位：只给 X、Y、所在位置
  • 藏道路上的路障；建筑的着火、温度、烧毁度、破损度
  • 藏其他单位的 HP、伤害、被埋深度、体力
  • 不给平民一个都不给，只能靠后面自己看到
  • 配置也只给白名单：思考时间、电台参数、水罐容量、灭火射程与上限、清障速率、感知精度、各兵种数量。地图文件本身不给
3
智能体 · 组装自己

照装配单把模块全部造出来

  • 读 config/module.cfg，按"我是什么兵种"挑出对应的 DefaultTacticsXxx.* 槽位
  • 每个模块的构造函数在这一步跑：用 mm.getModule("槽位名") 把依赖的兄弟模块挂进来
  • 这一步只做接线，不算任何东西
4
智能体 · 开电台

订阅频道，然后才能"听见"别人

  • 发 AKSubscribe(频道号列表)。每个兵种能订阅几个是写死的：小队 2 个、指挥中心 2 个（本图配置）
  • 想订阅的频道数超过上限 → 服务器只写一行警告，直接不处理，智能体那边毫无反馈。这是"明明写了通信却静默失灵"的最常见原因
  • 注意：说话不需要订阅，听才需要
5
智能体 · 开局就一次

建好"整张图都不会再变"的那份底稿

  • 赛前预计算模式：precompute(pd) 算完写盘存档
  • 正式比赛：有存档走 resume(pd) 读盘；没存档走 preparate() 现场算
  • 典型内容：分区、建筑邻接表、干线路网、拥堵热点
每回合循环
一回合 = 1 秒（kernel.agents.think-time），本图共 270 回合
6
服务器

先算感知，再等命令

  • 时间 +1，先用上一回合收到的消息跑一遍电台 → 消息天然延迟 1 回合
  • 对每个智能体做视线感知（射线打出去，被建筑挡住就看不到），算出这一回合的变化集
  • 把「时间 + 变化集 + 听到的消息」打包成 KASense 发出去
7
智能体

收、更新、算、回一个命令

  • KASense 被拆成两半：变化集进世界模型，消息进信箱
  • updateInfo()：读变化集、读信箱，更新内部状态
  • calc()：算这一回合该干什么，结论挂在模块自己身上
  • 战术层来取：getTarget() / getResult() / getAction()
  • 翻成动作命令发回服务器：AKMove / AKRescue / AKExtinguish / AKClear / AKLoad / AKUnload / AKRest
  • 一个单位一回合只能发一个动作命令，发两个第二个直接被丢掉
8
服务器

过滤 → 执行 → 合并 → 算分

  • 过滤：时间不对的、被冻住的、死了的、被埋的、重复发命令的，全部丢掉
  • 交给各模拟器执行（交通、倒塌、火灾、清障）
  • 结果合并回世界模型，更新比分，进入下一回合
三个兵种的实际决策链

消防队

BrigadeScout 找目标 → BrigadeNavigator 导航 → RescueOperation 挖人 → TacticalDisplacement 移动

警察

RiotSquadScout 找路障 → RiotSquadRouter 导航 → UESTCRouteSanitization 清障

医疗

SampleHumanDetector 找伤员 → UESTCReconnaissance 侦察 → MedevacTransport 搬运

四个必须讲清楚的坑

信息不是"看到"而是"变了"

给的是变化集，不是全量快照。要维持"我知道什么"，模块必须自己攒记忆，不然下一步就忘了。

看不到就等于不存在

平民开局一个都不给，路障和火也被藏起来。代码里直接假设"某建筑没着火"是危险的。

电台订阅超限是静默失败

服务器只写日志，智能体完全不知道。通信相关的 bug 优先查这里。

消息慢一回合

服务器先发感知、再收命令，所以这一回合发的消息，队友下一回合才收到。依赖实时协同的算法要考虑到。

服务器侧依据：kernel/ComponentManager.java、kernel/Kernel.java、standard/kernel/StandardAgentRegistrar.java、standard/kernel/LineOfSightPerception.java。 智能体侧依据：config/module.cfg 及各模块的 updateInfo / calc。
