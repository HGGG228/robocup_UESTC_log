## 一、先补一个缺口：一个人一个模块会撞车

你的分法是"每人一个模块"。这个分法在**兵种代码**上没问题，因为目录本来就是分开的。

但代码里还有一批**被所有兵种共用的文件**。我统计了 `config/module.cfg` 的引用次数：

| 文件 | 被几个槽位引用 |
|---|---|
| `PeopleConstraintDetector` | 11 |
| `NavigableWayConstructor` | 9 |
| `MergeGroupings` | 8 |
| `MotionAnomalyInspector` | 7 |
| `OptimalTrajectorySolver` | 5 |
| `ArterialRoadSegmenter` | 4 |
| `PickerDispatcher` | 3 |

改这几个文件不是"我改我的"，是**一次改动三个兵种一起受影响**。三个人要是都去动 `NavigableWayConstructor`，一定互相覆盖，而且谁也不知道分数变化是谁造成的。

**解决办法**：这批共用文件不按兵种分，单独划成"基础设施"，由 **P0（你）独占**。别人需要改动，提交需求单，由你统一改、统一验证。

## 三、每周固定节奏

| 时间 | 事 | 谁 | 时长 |
|---|---|---|---|
| 周一 | 挂机跑全量回归（18 局），出成绩表 | P4 | 3～4 小时挂机 |
| 周二 | 各自做实验 | 全员 | — |
| 周三 | 线上同步，只报"我卡在哪" | 全员 | 15 分钟 |
| 周四～周五 | 继续实验；**周五 24:00 前**交一行台账 | 全员 | — |
| 周六 | 组会 | 全员 | 2 小时 |
| 周日 | 补跑 / 休息 | — | — |

### 组会固定三段（顺序不许换）

1. **数据汇报（40 分钟）**：每人 5 分钟。格式固定 —— "我改了什么 → 哪张图涨了/跌了多少 → 我的结论"。
2. **深入议题（60 分钟）**：每周只议**一个**题，周三同步时定。
3. **分工确认（20 分钟）**：每人下周只认领**一个**目标，你记下来。

### 两种实验，别混

- **日常快跑**：各人自己跑 1～2 张图，10～20 分钟。用于快速迭代，随便跑。
- **全量回归**：6 图 × 3 种子，只由 P4 每周一跑一次。**这是唯一的合入门禁**，只有它能决定一个改动能不能进主干。

## 七、四条不许破的规矩

1. **开工前先 `git pull`，动手前先建自己的分支。** 分支名统一 `名字-干什么`，例如 `kongkeng-human-detector`。
2. **一次提交只做一件事。** 不许"改了寻路 + 顺手修了个 bug + 又调了参数"混在一起。
3. **任何人只管自己的文件。** 要动 `UESTC/module/algorithm/*` 或 `config/module.cfg`，先找 P0。
4. **没有数据的改动不许合入。** 台账上必须有一行"哪张图涨跌了多少"。
