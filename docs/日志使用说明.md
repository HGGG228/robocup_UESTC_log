# 智能体算法日志

新增日志使用 `[Telemetry]` 加单行 JSON，沿用 ADF `DefaultLogger`，以 INFO 级别记录。
原有救护 DEBUG 日志保留。日志只观察原有结果，不改变目标、路径或报文分配。

## 存放位置

相对于启动程序时的项目目录，正常运行的智能体按类型与 ID 写入：

```text
logs/FireBrigade/<ID>.log
logs/PoliceForce/<ID>.log
logs/AmbulanceTeam/<ID>.log
logs/FireStation/<ID>.log
logs/PoliceOffice/<ID>.log
logs/AmbulanceCentre/<ID>.log
```

这些文件由运行时创建；没有启动的智能体不会产生文件。当前仓库历史日志只有
`AmbulanceTeam`，新增代码不会为以前的仿真补造其他类型的记录。

当前 `module.cfg` 的消防站分配器使用已有的 `UESTCGoalDelegation`，
警察侦察执行器的清障动作使用已有的 `UESTCRouteSanitization`，避免引用缺失类。
若某类智能体在初始化时失败，应先处理启动错误，不能把缺少运行日志解释为该类本局没有任务。

通过 `bash launch.sh --map-name kobe1 -all` 启动时，运行期间写入 `logs/`，
运行结束后归档到 `log-archive/kobe1/<时间编号>/`；同地图每轮分别保存。
异常中断后的遗留日志会在下次启动前归档。详见 [地图日志用法](map-logs.md)。

## 事件与用途

所有事件带 `schema`、`time`、`agent`、`type`、`event`、`module`。

| event | 记录内容 | 用途 |
| --- | --- | --- |
| `tick` | 自身状态、位置、上一回合执行动作及其回合号 | 看挖掘、装载、移动、休息和停滞情况 |
| `decision` | 选中目标、目标状态、候选/搜索/排除计数等模块字段 | 分析选人、搜索与跨区任务 |
| `path` | 起终点、是否找到路径、路径节点、长度、距离和计算耗时 | 分析不可达、绕路和寻路开销 |
| `assignments` | 中心输出的单位到目标映射，含空分配 | 分析重复派遣和未分配单位 |
| `commands` | 指挥中心生成的指令条数 | 对照分配与通信是否接通 |
| `subscription` | 请求订阅的频道与订阅限制 | 发现重复订阅和配置问题 |
| `communication` | 待发/装箱报文类型、唯一消息数、复制次数和各频道字节数 | 分析过滤、重复发送与带宽使用 |

`decision` 是模块建议，框架可能选择其他分支；应结合下一回合 `tick`
里的 `action_time`、`executed_action_type` 和 `executed_action` 判断框架记录的动作。
动作是否在服务器成功生效，还需对照后续位置、埋深、载客状态或服务器日志。
`subscription` 表示提交了订阅请求，不等于服务器确认。
`communication` 表示本地打包结果，不等于对方收到；`not_packed` 可能来自过滤或带宽限制，
不能直接当成网络丢包率。跨局比较时请按 `log-archive/` 下的地图和时间目录选取整轮日志。

## 查看方式

在项目根目录打开 PowerShell，例如查看消防结构化记录：

```powershell
Select-String -Path .\logs\FireBrigade\*.log -SimpleMatch '[Telemetry]'
```

解析一名智能体的记录（将 `123` 替换为实际 ID）：

```powershell
Get-Content .\logs\FireBrigade\123.log | ForEach-Object {
    $marker = $_.IndexOf('[Telemetry]')
    if ($marker -ge 0) {
        $_.Substring($marker + 11).Trim() | ConvertFrom-Json
    }
} | Where-Object event -eq 'decision' | Format-Table time, module, target
```

优化前后使用相同地图、种子和回合数，对比目标切换、空等回合、救援/运输动作、
不可达次数、寻路耗时与通信装箱数量，最终收益仍以服务器成绩和仿真结果为准。

日志有额外序列化与磁盘开销。每回合只记录汇总，目标决策的重复读取会去重；
大图仍建议关注 `path` 的记录数量和每局文件大小。

## 本次验证范围

本次同步已使用 Java 21、Gradle 8.7 和真实 ADF/RCRS 依赖编译整个项目。
工具类另有独立检查覆盖 JSON 转义、未定义属性、去重、跨回合、动作回合关联、
空路径和异常隔离；独立检查使用真实 RCRS 实体和 log4j，ADF 上下文与日志器使用最小替身。
这些检查不能替代真实服务器上的完整救援仿真。

首次实际运行应确认六类日志文件及 `[Telemetry]` 记录均已出现。
若实际 ADF 日志设置禁用了 INFO 或无法取得日志器，会在标准错误中输出一次
`[TelemetryError]`；需检查实际日志配置，不能仅凭埋点存在认定文件已经落盘。
